## Test-construction note (O6)
The concurrent write fires from a wrapper on `updateProperty(ForOrg)`, which both the old and new code call after the read. It is an atomic `array_append` on its own pool connection. Two pool connections are warmed first, and the hook waits for the write for at most 3 s. My first two red attempts passed on the unfixed code, which made them false greens:
1. A cold Neon connect beat a 1.5 s window.
2. Drizzle's `db.execute` returns a **lazy thenable that re-runs on every `.then`**. `Promise.race` ran the append once (it was then overwritten), and the later `await` ran it **again** after commit, which hid the loss.

The final test pins one execution with `.then(() => undefined)`. It went red 3 times out of 3 on the unfixed code. The test timeout is 20 s because the locked path waits out the 3 s window by design.

## Deviations
- **O5 admin check: threaded `exec`, not hoisted before the tx.** Hoisting one `assertOrgAdmin` above the tx would still leave the inner `createDocumentForOrg`/`updatePropertyForOrg` asserting on the global `db`. Removing those inner checks would take authz out of the services. Passing the tx into `assertOrgAdmin` removes the second connection, and the check stays in every service. The default `db` keeps every other caller unchanged.
- **O1 also covers the first-visit branch.** It is behavior-identical there: no membership row can exist while a mirror row is missing, apart from the same race.
